# Phase 14 decisions

Built autonomously; each choice was made without asking.

1. **Guide book first, model optional.** The assistant is a side panel (rail "Ask" button, Help ▸ Assistant, F1) in every view. With no model it searches the guide book (`docs/guide/*.md`, compiled into the program by `build.rs`, so a PC without the docs folder still has it) and answers with the best section's text and the list of sections used. The guide book on screen is the same text as the notes.
2. **Search without a new dependency.** Notes are split at `##` headings; BM25 word weighting, heading and title words ×3, a small synonym list (NPL, FTP, EVE, "Excel", …), the question's shape (how / what is / error) lifts the matching heading kind. At least half of the question's informative words must be in a section, otherwise "The guide book does not cover this". The README (a list of links) is not searched.
3. **Never calculates.** A request for a figure ("calculate NIM for 4,500 Cr at 9.5%", "how much is…") is answered "I do not calculate numbers" plus the tool's note. "How is NIM calculated" and "formula for duration" are explanations and are answered. A model's answer is checked: any number that is in neither the sources nor the question (list markers aside) makes the model wording unseen; the guide's own text is shown with a note saying why.
4. **Model = llama.cpp `llama-server` + a GGUF file, in `portable_data/assistant/`.** No Rust LLM crate was added: that needs a C++ build in CI and would bloat the exe. The user copies the model and the unzipped llama.cpp folder once by USB; MicroParquet starts the server on `127.0.0.1` (a free port), talks plain HTTP to it with the standard library, and stops it on exit. No dependency added. Windows: no console window. Loading is user-started ("Start the model"); it auto-starts afterwards until stopped.
5. **Grounded and general modes.** With sections found, the model gets only those (≤3, ≤6,000 characters) and rules to answer from them and cite [1], [2]. With none, it may explain a banking / ALM / maths concept with no numbers, labelled "Not from the guide book". A calculation request never reaches the model.
6. **Privacy.** Only the question and guide sections go to the model; no table data, no schema, no file names. Questions and answers live in memory only. Loopback only.
7. **Not tested with a real model here** (none available in the build container); the HTTP client is tested against a stand-in server (plain and chunked replies), detection and refusals by tests. Please try once with a real model (see the guide note "Assistant").
8. **Open items for the owner.** (a) Added after the first report: twelve guide notes for Phases 11–13 (keep/drop and reverse sign, forecasting, ARIMA, variance bridge, budget and targets, target bands, rolling measures, what-if, drill-through, top movers, saved views, chart notes). Written from the Phase 11–13 decision docs and the screen labels in the code; their small examples are worked by hand, not produced by tests, so please check them against the screens when you next use each tool. (b) Which small model works best for this PC is untested; a 3B instruction model at 4-bit is the suggested start. (c) The panel is not the Ctrl+K search; "Find the tool" fills that search with the note's title.
